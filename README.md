# 后端工程师转向 AI 推理平台

本仓库记录一项在职 12 个月转型：把多年后端研发与通信/专网经验，迁移到 **模型服务、AI 平台后端和推理基础设施**。目标是交付一个可运行的平台、两份可复现技术报告，并用面试反馈验证岗位匹配度。

目前的履历信息仅有“多年后端研发”和“通信/专网经历”；具体语言、项目规模、Kubernetes/GPU 生产经验及可公开业绩仍待核实。岗位对照不会把待核实项写成已有技能。

## 可交付成果

| 成果 | 验收方式 |
|---|---|
| 推理平台旗舰项目 | 陌生人按 README 能启动服务、运行基准测试、查看指标并复现一次故障 |
| 容量与延迟报告 | 固定模型/硬件/版本/负载，保留 TTFT、TPOT、吞吐、错误率、显存及原始数据 |
| 优化或多卡报告 | Profile 或拓扑证据、对照实验、正确性检查、端到端收益及适用边界 |
| 求职反馈 | 第 6 月开始试投，记录简历转化、面试追问与下一步技能取舍 |

计划每周投入 **12 小时主任务 + 3 小时机动**。单月只设一个硬交付；时间不足时先保证可运行代码、数据和文档。详细安排见 [改进版 12 个月计划](AI_Infra_12个月转型计划_改进版.md)，岗位来源和缺口见 [16 条目标岗位 JD 对照](docs/目标岗位JD对照_2026-09-15.md)。

## 12 个月 milestone

| 月份 | 里程碑 | 必须留下的证据 |
|---|---|---|
| M1 | 跑通小模型推理 | 正确计时、显存记录、环境清单和请求链路 |
| M2 | 解释 prefill/decode 与 KV Cache | 最小实验、容量估算和原始数据 |
| M3 | 推理服务 V0 | vLLM、网关、流式转发、超时、健康检查与运行说明 |
| M4 | 第一份容量报告 | 固定条件的延迟/吞吐/错误率扫描和可重新计算的数据 |
| M5 | 可观测与故障演练 | Dashboard、告警依据、一次故障定位记录 |
| M6 | 平台 V1 并开始试投 | 部署、CI、runbook、陌生人试跑结果和首轮岗位反馈 |
| M7 | 选择深化支线 | 根据 JD/面试反馈选择性能优化或分布式/算力平台 |
| M8 | 完成诊断到改动闭环 | Profile/拓扑、正确性检查、改动和失败实验 |
| M9 | 第二份技术报告并扩大投递 | 优化收益或单/双卡扩展数据，明确适用边界 |
| M10 | 补一个岗位高频系统缺口 | NUMA/网络、GPU 调度容量或国产硬件适配案例之一 |
| M11 | 获取外部反馈 | 有测试的上游 PR，或同行试跑并修复反馈 |
| M12 | 平台 V2 与求职冲刺 | Release、两份报告、定向简历、架构讲解和投递复盘 |

## 当前第一步

先核实并记录过去 2–3 个能公开讲述的项目：你的职责、系统规模、性能或可靠性问题、采取的措施与结果。随后按 M1 做小模型推理和正确计时实验。岗位来源检索于 2026-09-15；实际投递前重新确认招聘状态、地点和硬条件。
